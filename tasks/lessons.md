# Lessons

- Do not assume the original workspace path is still current after the user says they renamed the project folder. Re-discover the active project directory and restart servers from that folder.
- Do not present optional provider metadata headers as required `.env` setup. For OpenRouter, keep the required setup focused on `OPENROUTER_API_KEY`; only mention `HTTP-Referer`/`X-Title` if the user specifically wants request attribution metadata.
- In local dev, a project `.env` file should override inherited shell environment values; otherwise stale provider keys can survive server restarts and produce misleading auth errors.
- For the current NewsletterCreator scope, do not recommend issue/history persistence by default. Persist only user configuration such as custom sources and last selected models unless the user asks for saved newsletters, publishing history, accounts, or collaboration.
- Keep source types aligned with the product language. For NewsletterCreator, expose sources as RSS feeds or website scrape targets; do not introduce provider-specific search shortcuts like HN Algolia unless the user explicitly asks for them.
- When adding compact controls inside broader button containers, check CSS specificity against parent rules such as `.toolbar button`; use selectors specific enough to preserve intended dimensions.
- When helping with Mailchimp setup, state the required `.env` values up front: `MAILCHIMP_API_KEY`, `MAILCHIMP_LIST_ID`, `MAILCHIMP_FROM_NAME`, and `MAILCHIMP_REPLY_TO`.
- For this app, treat Mailchimp as a single-user HTML campaign integration. Do not add dashboard/database complexity for switching templates or section maps unless the user explicitly asks for multi-template support.
- For Mailchimp preview issues, avoid `template.sections` unless the configured Classic template has verified editable default-content sections. The reliable preview path is a regular campaign followed by full `html` plus `plain_text` content.
- For website source gathering, do not treat any nonzero scrape result as complete. If direct scraping returns fewer than the source limit, supplement from the fallback feed before applying the limit.
- When reproducing a source-gathering bug, use the exact persisted source URL from preferences. Similar domains can have very different fallback coverage, as with `the-decoder.de` versus `the-decoder.com`.
- After fixing a deployment failure locally, compare the failed deploy commit with local `HEAD` and the remote branch before declaring the fix ready; Vercel only sees pushed commits from the connected repository.
- For NewsletterCreator website sources, do not describe or implement scraping as plain regex/link extraction when the user expects AI scraping. Website source extraction should use an AI model to identify article candidates from fetched page content.
- When adding any AI-powered workflow in NewsletterCreator, expose both the system prompt and model selection in the relevant app section instead of hiding them in server code or env-only settings.
- For NewsletterCreator prompt work, do not expose only the chat system prompt. Any hidden user/task prompt template must also be visible, editable, and tied to persistence when the user asks for saved prompts.
- Do not make model-dependent dropdowns appear like single-option controls before the model catalog is loaded. Auto-load or clearly populate OpenRouter model choices for any model selector added to the app.
- If Gather news depends on the AI scrape model, disable the Gather news button until `Load models` has populated the model catalog and a scrape model is selected.
- For Vercel team deploys, align git author email with a Vercel team member email before pushing, instead of relying on GitHub org OAuth labels to satisfy commit-author verification.
- Before clearing generated `.next` output on Windows, stop all Next dev/build processes for this repo. A live dev server can leave `.next/dev` metadata partially deleted and cause missing `app-paths-manifest.json` 500s.
- When the user is running `npm run dev` in their own terminal, do not leave a Codex-started background Next dev server running on the same repo/port. Stop Codex-owned dev servers after verification unless the user explicitly wants it kept alive.
