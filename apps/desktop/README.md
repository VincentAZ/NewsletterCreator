# Desktop development preview

## Implemented

- Electron with a sandboxed React/Vite renderer, context isolation, validated typed IPC and denied renderer network/permission requests.
- SQLite revision-checked profiles/issues, serialized local autosave, restart recovery, assets, JSON backups and validated restore with a recovery backup.
- Library, Studio, and Settings navigation, with contextual newsletter settings and blank/Community/Small Business/AI News starting points. Only a newsletter name is required.
- Focused block editor with direct text editing, duplication, keyboard movement, source inspection, targeted rewrite instructions, whole-issue replacement confirmation, and scoped undo. Ctrl/Cmd+Z outside fields undoes block operations; fields retain native text undo.
- Searchable/filterable source inbox with All/Selected views, honest collection outcomes and retry, and Add to issue without AI. An included source links back to its block.
- Session-only resizable source/live preview panels: both at 1600px+, one at 1100–1599px, drawers below 1100px. Shared email rendering for unsaved live preview, full desktop/mobile/plain-text review, and self-contained HTML export.
- Explicit local LM Studio/ComfyUI providers and optional OpenRouter/fal providers. Structured copy is validated; source IDs cannot be invented. Model failures leave the saved issue unchanged.
- Native setup with platform-specific manifests, verified/resumable downloads, isolated Python virtual environment, built-in ComfyUI SDXL graph, hardware/disk/port checks, cancellation, repair and owned-process shutdown.
- Mailchimp hosted image upload, persistent campaign/asset checkpoints, uncertain-create recovery, draft status checks and stored-HTML verification. No send/schedule routes.
- Read-only Supabase import: imported profiles retain Serpico branding and sources; all legacy model/prompt fields are archived in the local profile and backups. Reimporting the same row returns the existing imported profile. Cloud providers are never activated by import.

## Runtime boundaries

`src/main/runtime-manifest.json` pins llmster 0.0.25-1, uv 0.13.1, ComfyUI v0.41.0, Qwen3 4B Q4_K_M and SDXL 1.0 artifacts with official source URLs and SHA checks. Model downloads alone total about 9.4 GB decimal. Some publishers do not return archive sizes in HEAD responses; setup labels unknown sizes explicitly. Python 3.12.12 and PyTorch 2.9.1 are selected explicitly. Transitive dependencies use committed hash-locked wheel sets for Linux/Windows CPU and CUDA 12.8, and Apple Silicon Metal on macOS 14+. The installer uses `uv pip sync --require-hashes --only-binary :all:`; it does not build unpinned native dependencies. Regenerate locks deliberately with `node apps/desktop/scripts/lock-python.mjs` and review the result before changing the manifest.

Engine archives/models are downloaded at the user's request, not redistributed in installers. Users review linked publisher terms during setup. Model repository terms and engine terms remain independent.

The application owns its engine binaries, ComfyUI virtual environment, model downloads and only child processes it directly starts. LM Studio's upstream bootstrap also initializes its **standard user data directory**. This is not full application-directory isolation. Existing LM Studio installations are detected and never overwritten or taken over. Do not claim the stronger isolation gate has passed until a supported upstream isolated-runtime mechanism is proven. Source material is passed as untrusted reference data; it is never executed.

Inference requests are serialized, but existing engines may retain resident models. ComfyUI cancellation removes this application's queued prompt; it deliberately does not interrupt a shared server's already-running job. Cancellation stops an app-owned image process to release memory; restart it from setup before the next image. Automatic text-model eviction and cancellation behavior under memory pressure still need real hardware validation.

## Verification performed and remaining gates

Automated tests cover local revisions/restarts, backup validation/assets, unrelated newsletter topics, targeted generation, malformed output and no cloud fallback, partial/all-source collection failures, resumable integrity-checked downloads, queued cancellation, private-address rejection, port conflicts, owned-process-tree cleanup and Mailchimp draft retry reuse/content verification. CI builds unsigned Linux AppImage, Windows NSIS and Apple Silicon macOS DMG previews on their native operating systems and launches each unpacked application. The Linux Electron tests exercise manual writing, source-to-block insertion and duplicate prevention, scoped undo, whole-issue replacement, rewrite failure/retry, image persistence/export, save conflicts, dialogs, keyboard resizing, four window sizes and 125% zoom. Backend destination traces show zero startup requests and loopback-only fixture inference; Chromium net logs show no HTTP(S) requests during the tested workflow after session spellchecking is disabled. Those automated workflow tests use a local fixture model server.

On October 16, 2026, separate real-engine tests passed on Linux with an NVIDIA RTX PRO 6000 Blackwell (96 GB VRAM): targeted text generation through an existing user-owned LM Studio server; official pinned ComfyUI/Python/PyTorch/SDXL installation into the application's validation directory; real image generation; owned-engine stop/restart; cancellation followed by restart; and image/issue persistence after application restart. An OS-level trace of the application and managed ComfyUI children during generation/recovery observed only loopback network destinations. The existing LM Studio process was outside that trace. This does **not** establish complete-stack telemetry freedom, managed Qwen installation, a clean-machine installation, or behavior on lower-memory hardware.

The [cross-platform run for `7caddf3`](https://github.com/VincentAZ/NewsletterCreator/actions/runs/38953965903) passed Windows, macOS 15/Apple Silicon and Linux packaging and native application launch checks. The personal Supabase Newsletter Generator project also received the existing `revision bigint not null default 1` migration on October 16. A transaction compared all pre-existing preference fields before and after the addition and would have rolled back on any difference; the check passed. No preference fields or rows were removed.

The following are **release blockers**, not claims of completed validation:

- Real clean-machine managed installation and text/image inference on NVIDIA Windows/Linux and Apple Silicon macOS. The Linux development host has existing engines; its successful managed image test cannot stand in for clean-machine or other-platform tests.
- Fully isolated LM Studio data, managed Qwen inference, real-engine memory-pressure behavior and network capture including the text runtime. Managed ComfyUI cancellation/restart and the app's own network boundary have passed independently.
- Live Mailchimp draft/image/content verification with personal credentials and the chosen audience. Mocked API tests do not replace a live handoff.
- Authenticated dashboard/API verification for the old web release. Anonymous hosted access currently fails closed; the Supabase revision migration is now applied. The browser opens Vercel under the `<team>` team (displayed as “<account>”); automatic approval review blocked further inspection under the repository's personal-account rule. Account-scope confirmation is required before proceeding there.
- Signing/notarization credentials and platform installation smoke tests. Until supplied, installers are labeled development previews.

Keep this branch separate from `main` until the release gates are met.

## Reproducing hardware and live-service checks

Build the desktop first. These opt-in scripts use isolated validation data under the ignored `apps/desktop/release/production-validation` directory. They do not replace the user's newsletter database or take ownership of existing engines. `NEWSLETTER_VALIDATION_DATA` can select a different validation directory.

- `node --import tsx tests/desktop-real-engines.mjs --install-image`: installs the pinned managed image stack after `NEWSLETTER_ACCEPT_ENGINE_TERMS=1` explicitly records that the linked publisher terms were reviewed. Allow 30 GB free space and the manifest's engine/model downloads. It uses port 18188 and preserves existing ComfyUI on port 8188. On headless Linux prefix the command with `xvfb-run -a`.
- `node --import tsx tests/desktop-real-engines.mjs --managed-image`: tests the previously installed validation stack without downloading it again. Set `NEWSLETTER_TEXT_MODEL` to an available model to also check the existing LM Studio server at port 1234; `NEWSLETTER_LM_URL` can select another loopback server. Reports are saved as `evidence.json`.
- For Linux OS-level runtime capture, set `NEWSLETTER_ELECTRON_WRAPPER` to the absolute path of `tests/trace-electron.sh` and `NEWSLETTER_NETWORK_TRACE` to an absolute output prefix before the real-engine test. This requires `strace`. Summarize with `node tests/summarize-network-trace.mjs <prefix>`; external or unrecognized Internet destinations fail the check. This capture includes the application and children it starts, **not** independently running engines. Capture installation separately from inference because installation intentionally downloads artifacts.
- `node --import tsx tests/desktop-live-mailchimp.mjs`: requires explicit `NEWSLETTER_LIVE_MAILCHIMP=1` plus securely configured `MAILCHIMP_API_KEY`, `MAILCHIMP_LIST_ID`, `MAILCHIMP_FROM_NAME`, and `MAILCHIMP_REPLY_TO`. It creates a clearly labeled synthetic draft, uploads a test image, simulates a lost verification response, restarts storage, retries the same campaign, verifies hosted images/content and draft status, and retains the draft and evidence for inspection. It never sends or schedules. Subsequent runs reuse the same validation issue/campaign. This check remains unrun without personal test credentials.

## Signed release candidates

The October 16 Linux validation also launched the actual AppImage with Chromium's normal sandbox enabled, using AppImage's extract-and-run mode to avoid a FUSE dependency. To repeat: `NEWSLETTER_PACKAGE_NATIVE_SANDBOX=1 APPIMAGE_EXTRACT_AND_RUN=1 xvfb-run -a node tests/desktop-package-smoke.mjs apps/desktop/release/NewsletterCreator-0.1.0-linux-x86_64-preview.AppImage`. Native Windows/macOS package checks keep their normal sandbox settings; Linux hosted CI uses `--no-sandbox` because runner sandbox support differs. The macOS build runner uses macOS 15 because the [macOS 14 hosted image is being retired](https://github.com/actions/runner-images/issues/13518); this does not change the managed runtime's macOS 14 minimum requirement.

Ordinary CI continues to produce unsigned development previews. The separate, manually triggered **Signed desktop release candidates** workflow uses `electron-builder.signed.cjs`, requires signing, checks the Windows installer/application signatures, and validates macOS signing, Gatekeeper acceptance and notarization. It never publishes a release or merges branches. Its configuration has been validated locally; actual signing remains unverified until credentials are supplied.

Configure personal-repository secrets `WIN_CSC_LINK`, `WIN_CSC_KEY_PASSWORD`, `MAC_CSC_LINK`, `MAC_CSC_KEY_PASSWORD`, `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, and `APPLE_TEAM_ID`. Certificate links may contain base64 certificate data as supported by electron-builder. Keep secrets out of source files and chat. The workflow fails before installation/build if required credentials are absent. A signed candidate still must pass the real installation, inference and live-service gates above before it is a production release.
